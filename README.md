# markcleanse

AI provenance and watermark forensics for images and documents. Scans a file, a
folder, or a whole tree; reports what evidence of AI generation each file
carries, how strong that evidence is, and — where possible — which generator
produced it. Then strips what shouldn't be there.

Zero dependencies. Python 3.10+. Uses `exiftool` if it happens to be installed,
works fine without it.

```
$ markcleanse ~/client-assets

FILE                          VERDICT         ATTRIBUTED TO                 T  EVIDENCE
────────────────────────────────────────────────────────────────────────────────────────
hero-shot.png                 AI-GENERATED    Stable Diffusion (A1111…)     A  PNG embeds full generation parameters…
cover.jpg                     AI-GENERATED    OpenAI DALL·E 3               A  C2PA manifest declares digitalSource…
brief.pdf                     AI-GENERATED    —                             A  Zero-width characters decode to a hi…
deck.pdf                      AI-DECLARED     Gamma                         B  Document metadata Producer = "Gamma …
banner.png                    WATERMARK?      Google Gemini                 U  Google Gemini embeds SynthID, which …

42 scanned  3 AI-GENERATED  1 AI-DECLARED  1 WATERMARK?  1 SIGNED-CAPTURE  36 clean
```

The table lists what is flagged; the summary counts every verdict, which is why
`SIGNED-CAPTURE` — a manifest positively asserting a camera origin — appears in
the totals but not the rows. `-a` lists everything.

**[→ DETECTION.md](DETECTION.md)** is the full catalogue: every detection type,
a runnable example file for each in [`samples/`](samples/), and an explicit list
of what is *not* covered. It is generated by scanning those samples, so it
cannot drift from the code.

```bash
markcleanse samples/                            # every detection type at once
markcleanse samples/c2pa-transplanted.png -v    # full evidence for one
```

## Read this first: what is and isn't possible

This space is full of tools that output "87% AI" and mean nothing by it.
markcleanse never produces a confidence percentage, because an honest one cannot
be computed. It reports **evidence tiers** instead.

### What it detects with certainty

| Evidence | Where | Tells you |
|---|---|---|
| **C2PA / Content Credentials** | JPEG APP11, PNG `caBX`, WebP `C2PA`, AVIF/HEIC/MP4 `uuid` box | Exact generator, actions taken, signing certificate — **cryptographically verified** |
| **PNG generation parameters** | `tEXt`/`zTXt`/`iTXt` chunks | Full prompt, model hash, sampler, seed, LoRAs |
| **ComfyUI workflow graphs** | PNG `prompt` / `workflow` chunks | Entire node graph and checkpoint filenames |
| **IPTC `DigitalSourceType`** | XMP in any container | Standardised machine-readable "this is AI-generated" |
| **Hidden Unicode payloads** | Any text or document | Decoded watermark/beacon string |
| **ASCII whitespace payloads** | Plain-text files | Decoded string hidden in word/sentence/line-end spacing |
| **Stealth pnginfo** | PNG alpha/RGB least-significant bits | Decoded prompt and seed — *survives metadata stripping* |
| **Metadata generator names** | EXIF `Software`, XMP `CreatorTool`, PDF `/Producer`, DOCX `<Application>` | Named tool |
| **Assistant leakage** | Any text | Chat output pasted verbatim |
| **Vendor watermark notice** | Text/images attributed to Claude, Gemini, Meta | Tier **U** — names the scheme and where it *can* be verified |

### What it cannot detect — and neither can anything else you can buy

- **Google SynthID** (Gemini, Imagen, Veo, NotebookLM) — an invisible
  pixel/token-space watermark decodable only with Google's private key. The
  SynthID Detector portal is waitlisted and there is **no public
  specification**, so no third party can implement detection. markcleanse
  reports *"Google-family origin indicated, SynthID present but unverifiable"* —
  tier **U** — rather than guessing.
- **Meta's Stable Signature** — published, but no public detector exists.
- **Statistical text watermarks.** As of **2 August 2026** these are real and
  deployed, driven by EU AI Act Article 50: Anthropic Claude (announced
  14 Aug 2026) and Google Gemini both carry SynthID-Text. None are locally
  detectable, and the reason is structural — the key biases the model's choice
  between equally good words, so **no character is inserted and no artefact is
  left in the file**. There is nothing for a scanner to find; verification
  requires the vendor's own API. A product claiming to detect these without the
  vendor's key is lying to you.

The exception worth knowing: **stealth pnginfo** (NovelAI, A1111's
`stealth_pnginfo`) *is* pixel-embedded but uses a published encoding, so it is
decoded in full — and it survives every metadata strip, which is exactly why it
is worth checking.

### The rule that matters

> **Absence of evidence is not evidence of human authorship.**

A screenshot, a re-save, a social-media upload, or `exiftool -all=` strips every
signal in the table above while changing nothing a viewer can see. A clean
result means "no markers survived", never "a human made this".

Conversely, metadata is forgeable. EXIF and XMP claims (tier B) are a string
anybody can write. C2PA manifests are not — see below.

## C2PA verification

Every manifest found is checked four ways. The first two need nothing but
`hashlib`; the last two use `cryptography` when it is installed and fall back to
this project's own ECDSA/RSA/Ed25519 implementations when it is not.

| Check | Catches | Needs |
|---|---|---|
| **Asset hash binding** — all three C2PA hard bindings: `hash.data` (JPEG/PNG/WebP), `hash.bmff` v1–v3 (AVIF/HEIC/MP4), `hash.boxes` (named PNG chunks / JPEG segments) | a manifest lifted from another file, the file edited after signing, or a box inserted/reordered | stdlib |
| **Assertion hashes** | the manifest's own contents altered after signing | stdlib |
| **COSE signature** | a wholesale forgery | crypto |
| **Certificate chain** | leaf→root links, validity dates, CA constraints | crypto |
| **Certificate profile** | a credential not permitted to sign C2PA claims — wrong curve, short RSA key, missing/conflicting EKU, self-signed CA | stdlib |
| **Revocation** | a signing certificate that was revoked — read from the OCSP response stapled into the manifest, with the responder's signature verified | stdlib |

A manifest that fails any check is reported as **`PROVENANCE-FORGED`**, and its
provenance claim is demoted from tier A to tier C — because a manifest that
isn't honest about *which file it describes* can't be trusted about what made it
either. That verdict outranks everything else in the report.

```
$ markcleanse suspect.png -v

suspect.png
  png · 1,965 bytes · PROVENANCE-FORGED
  [A] integrity.c2pa.binding_mismatch
      C2PA manifest is NOT bound to this file — the hash in the claim covers
      different bytes. The manifest was copied from another asset, or the file
      was modified after signing
      signature:  valid          <- the manifest itself is intact...
      binding:    mismatched     <- ...it just doesn't belong to this file
      chain:      verified
```

**Cross-checked against the reference implementation.**
`tests/crosscheck_c2patool.py` runs both this tool and **c2patool** (the CAI
reference implementation) over the same files and compares signature, binding
and assertion verdicts field by field. On real production files: **106/106
agree, 0 wrong.** Verified against **23 production manifests** from ChatGPT,
Sora and Google Gemini, signed by Truepic Lens and Google C2PA Media Services.

A verified chain proves the manifest was signed by whoever holds that key — not
that the key belongs to a legitimate signer. So `trust` is reported separately
and the default is `no-trust-list`, never `trusted`:

```bash
bash tools/update-trust-list.sh        # fetch the official C2PA trust list
markcleanse ~/assets --trust c2pa      # ...and make trust a real decision
```

**[→ docs/c2pa.md](docs/c2pa.md)** — trust lists, prior art, the full
cross-check results, and why revocation is checked offline by default.

## Evidence tiers

| Tier | Meaning | Use it for |
|---|---|---|
| **A** | Embedded generation record — a *verified* C2PA manifest, PNG generation parameters, IPTC `digitalSourceType`, decoded hidden payload | Report as proof |
| **B** | Self-declared metadata naming a generator, or verbatim assistant phrasing | Report as strong evidence; note it is strippable |
| **U** | A watermark is indicated but is verifiable only by the vendor | Report as "origin indicated, watermark unchecked" |
| **C** | Heuristic — output dimensions, unusual whitespace, and prose stylometry if you passed `--stylometry` | Internal triage only. **Never present alone as proof** |

Verdicts map from the highest tier present: `AI-GENERATED` (A), `AI-DECLARED`
(B), `WATERMARK?` (U), `SUSPECT` (C), plus `SIGNED-CAPTURE` for files whose C2PA
manifest positively asserts a camera origin, and `NO-EVIDENCE`.
`PROVENANCE-FORGED` overrides all of them when a manifest fails verification.

Text analysis is two separate things: hidden-character and whitespace payloads
(evidence — they are physically in the file), and prose stylometry, which is
**opt-in** via `--stylometry` because it is the only detector here that can be
wrong about a human. **[→ docs/text.md](docs/text.md)**

### Try it on this README

```
$ markcleanse README.md docs/ --stylometry
README.md       SUSPECT   C  Prose style moderately consistent with LLM generation (score 42.7/100…
docs/text.md    SUSPECT   C  Prose style moderately consistent with LLM generation (score 64.6/100…
```

That is the module behaving correctly, and it is precisely why it does not run
unless you ask for it. Stylometry measures resemblance to patterns common in
LLM output — parallel structure, short declarative sentences, em-dashes, even
paragraph lengths. Technical documentation written to be scannable has those
properties by construction. The score cannot tell you who typed a page, and
nothing here claims it can: tier C, never proof on its own, off by default.

Every other detector in this tool reports what a file *contains*. This one
reports what its rhythm *resembles*. Those are different kinds of claim, and
only the first one belongs in an argument.

## Removing what was found

```bash
markcleanse cleanse <paths> [--dry-run] [--out DIR] [--in-place] [--categories ...]
```

Four categories. The first three are on by default:

| Category | Removes | Default |
|---|---|---|
| `hidden` | zero-width chars, Unicode Tags, variation-selector payloads, bidi overrides, homoglyphs, whitespace stego | yes |
| `privacy` | GPS, camera serials, owner/author names, timestamps | yes |
| `generator` | PNG generation parameters, `Software`, `CreatorTool`, XMP | yes |
| `provenance` | C2PA manifests | **no — explicit opt-in** |

`provenance` is opt-in because it is the one category that destroys a
*verifiable signed record* rather than an unverifiable string — including the
record that attests a photograph is a photograph.

Rewriting is **lossless and structural**: chunks and segments are dropped from
the container, image data is never re-encoded. Verified on real files — 11
images round-tripped with byte-identical pixels, 18 Office documents with every
content part preserved and only `docProps` removed.

Safety defaults: writes `name.clean.ext` alongside the original; `--in-place`
keeps a `.bak`; `--dry-run` shows the plan. After writing, the output is
re-scanned and anything still detectable is printed.

```
$ markcleanse cleanse report.docx
report.docx
  - [privacy] document properties (docProps/app.xml)   (68 bytes)
  - [privacy] document properties (docProps/core.xml)  (96 bytes)
  - [hidden] word/document.xml: 11 Unicode Tag characters
  → report.clean.docx (175 bytes removed)
  re-scan: no markers remain
```

That last line is a *re-scan of the output*, not an assumption. When something
survives, it is printed.

### What removal cannot do

**Pixel-space watermarks survive everything here.** Google SynthID and Meta's
Stable Signature are modifications of the image content, not metadata. They are
unaffected by stripping chunks, and are not reliably removed by re-encoding,
cropping or resizing either. A cleansed Gemini image scans as `NO-EVIDENCE`
locally and *remains detectable by Google*. The tool prints that warning every
time it touches an image, because a clean scan result is exactly when someone
would wrongly conclude otherwise.

Whitespace normalisation is a *visible* edit, so it only runs when a whitespace
payload is actually detected — a routine metadata scrub will not reflow your
prose. Emoji ZWJ sequences and script-required ZWNJ are preserved. PDF,
HEIC/AVIF and TIFF are refused rather than risked.

## Known gaps

A forensics tool you can't state the limits of is not usable in an argument.
The short version:

- **Nobody can do these** — pixel watermarks (SynthID, Meta) and statistical
  text watermarks both need the vendor. A screenshot or re-encode destroys
  every metadata signal.
- **Not implemented here** — video *frames* are never examined (container-level
  C2PA in MP4 is verified); `hash.collection` reports `unsupported` rather than
  guessing; RFC 3161 timestamps are displayed but not validated; CRL revocation
  is not implemented, only OCSP.
- **Inherently partial** — the generator name list is finite, the homoglyph
  table covers ~30 of several hundred confusables, and stylometry is
  English-only and trivially defeated by editing.

**[→ docs/limits.md](docs/limits.md)** for the complete list.

## Install

Nothing to install. Clone it and run:

```bash
python3 -m markcleanse ~/some-folder
```

To get a `markcleanse` command anywhere:

```bash
chmod +x markcleanse.sh
mkdir -p ~/.local/bin && ln -sf "$PWD/markcleanse.sh" ~/.local/bin/markcleanse
```

Optional extras, none required:

- `exiftool` (`apt install libimage-exiftool-perl`) — adds HEIC, AVIF, TIFF, RAW
  and dozens of extra XMP namespaces.
- `pypdf` — better PDF text extraction than the built-in content-stream parser.
- `cryptography` — faster, audited signature verification. Without it the
  bundled pure-Python implementations do the same job more slowly.

## CLI

```bash
markcleanse PATH [PATH...]

  -v, --verbose        full evidence dump for every flagged file
  -a, --all            list clean files too
      --json FILE      full report as JSON ('-' for stdout)
      --csv FILE       CSV summary — one row per file
      --md FILE        Markdown report, client-ready
      --stylometry     also score prose style for LLM tics (tier C, off by default)
      --no-exiftool    skip the exiftool enrichment pass
      --no-verify      skip cryptographic verification of C2PA manifests
      --trust FILE     trust anchors — PEM bundle, fingerprints, or 'c2pa'
      --revocation {off,stapled,online}   default 'stapled' — offline and private
      --only NAMES     run specific detectors only
      --no-recursive   don't descend into subdirectories
      --hidden         include dotfiles and dotdirs
  -j, --workers N      thread count
      --fail-on {none,any,confirmed}   exit non-zero for CI gates
```

Subcommands: `markcleanse cleanse` (remove markers) and `markcleanse report`
(standalone HTML you can hand to someone). Detector names for `--only`: `c2pa`,
`png_text`, `image_meta`, `stealth_png`, `documents`, `unicode_wm`,
`whitespace_wm`, `stylometry`.

```bash
# Vet a client deliverable before it ships
markcleanse ~/deliverables --md report.md

# Gate a build: fail if anything is confirmed AI-generated
markcleanse ./assets --fail-on confirmed -q

# Add the prose heuristic when triaging text you already suspect
markcleanse ~/drafts --stylometry

# Investigate a single file
markcleanse suspicious.png -v
```

## Web UI

A local drag-and-drop UI, stdlib-only — no pip install, no network:

```bash
python3 web/serve.py --open        # or double-click `Start markcleanse.sh`
```

Whole folders work. C2PA results render as a pass/fail checklist rather than a
JSON blob, so you can see *which* check failed at a glance. Anything with
removable markers gets a **Cleanse it** button; uploads are cleaned in memory
and handed back as a download, so a web page never writes to this machine. The
server binds to loopback only and refuses to do otherwise.

**[→ docs/web-ui.md](docs/web-ui.md)** — the launcher, cleansing from the UI,
reports, the text tab and the self-verifying docs tab.

## Reports

The deliverable — a scan you can hand to someone who does not have this tool:

```bash
markcleanse report ~/inbox -o report.html      # then open it; Ctrl-P saves a PDF
```

Self-contained: one HTML file, no network, no assets, so it still renders years
from now. Evidence comes before opinion — tier A and B findings are laid out
ahead of tier C heuristics, and the most serious verdict sorts to the top. And
the caveats travel with it, printed inside the document, because whoever reads
it will not have markcleanse in front of them.

## Tests

```bash
python3 tests/test_markcleanse.py   # no pytest needed
python3 -m pytest tests/ -q         # if you have pytest
```

The suite has two halves and the second matters as much as the first.
`test_no_false_positives` is a corpus of patterns that fooled earlier builds on
real files — emoji ZWJ sequences, bidi marks in UI accessibility dumps, Persian
ZWNJ, leading BOMs, Cyrillic place names in a gazetteer, NBSP in Office exports,
a consistent two-space-after-period habit, TypeScript source, and a file named
`CLAUDE.md`. Over-eagerness is the failure mode that destroys trust in a
forensics tool, so it is tested against directly.

**[→ docs/internals.md](docs/internals.md)** — library API, project layout, and
how to teach it a new generator.
